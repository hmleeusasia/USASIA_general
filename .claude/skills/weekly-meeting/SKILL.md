# 주간 IT 회의 (weekly-meeting, D-20261102-23)

회의록 원본은 드라이브 Meeting 폴더(구글 문서). 저장소에는 결정·To-do 요약과 링크만(금액·인사 소식 금지).

## A. 회의 전 (월요일 10:00 전, start-day에서 제안)
1. 드라이브 Meeting 폴더에서 가장 최근 `회의록 MMDDYY`를 찾는다 (search_files, 제목 기준 최신)
2. 사용자 승인 후 copy_file로 복사, 제목 `회의록 MMDDYY`(이번 월요일)
   - 지금까지의 누적 방식(이월 안건 + To-do)을 그대로 이어간다
3. 복사본에 넣을 것을 사용자에게 제안 (문서 직접 수정은 시트·문서 수정 도구가 있는 클라우드 계정이 하거나 사용자가 붙여넣음):
   - 지난주 To-do 중 todo.md에서 끝난 것 → "완료" 표시 후보
   - todo.md '지금'·새 티켓·메일에서 나온 안건 후보
4. 새 회의록 링크를 보고. 공유는 폴더와 같게(비공개), 공유 변경은 하지 않는다

## B. 회의 뒤 ("회의 정리" 요청 시)
1. 이번 주 회의록을 읽는다 (read_file_content)
2. 사용자가 적은 내용을 나눈다:
   - 결정 → 업무 기록 건 `### 회의 결정: 제목  #meeting #decision #<분야>` (본문에 회의록 날짜·링크). 틀·규칙에 관한 결정만 decisions.md
   - To-do → docs/users/<id>/todo.md (ID: 티켓 있으면 T-번호, 없으면 M-이름, 담당·기한)
   - 프로젝트 관련 → 해당 projects 허브 태그(#proj-…)
3. 애매한 줄(담당·기한 없음, 결정인지 메모인지 불명)은 묶어서 한 번에 질문
4. 업무 기록 `docs/log/YYYY/YYYY-MM-DD_<id>.md`, 커밋·push
5. 보고: 결정 N건, To-do N건(새/끝/이월), 물을 점

## 주의
- 회의록의 금액·인사 소식·IP는 저장소로 옮기지 않는다 (⚠ 표시만)
- 매장 약어는 docs/kb/store_codes.md
